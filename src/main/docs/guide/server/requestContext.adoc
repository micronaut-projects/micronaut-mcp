Declare a parameter of type `McpRequestContext` in a tool, prompt, resource or completion method to report progress, send log messages to the client, or check whether the client stopped waiting:

snippet::io.micronaut.mcp.docs.context.CatalogTools[project-base="test-suite-docs", tags="imports,clazz"]
<1> Sends a https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/progress[progress notification], if the client asked for progress with a progress token.
<2> Sends a https://modelcontextprotocol.io/specification/2025-11-25/server/utilities/logging[log message].

The parameter is not part of the tool's input schema or of the prompt's arguments.

Over the HTTP transport, the response to a request whose client accepts both `application/json` and `text/event-stream` becomes an event stream as soon as the method sends a notification: each notification is sent as an event while the method runs, followed by the result. A request that sends no notification, or whose client only accepts JSON, is answered with JSON. Only requests for a primitive that declares an `McpRequestContext` parameter may become an event stream, and a client that accepts `text/event-stream` with a quality of `0` is answered with JSON. When the client goes away, the request is cancelled and `isCancelled()` returns `true`. If a slow client lets more than 256 events pile up, further notifications are dropped, but the result is always sent.

When a primitive declares an `McpRequestContext` parameter, the server advertises the `logging` capability, since it may send log messages.

`elicit` and `sample` send requests to the client, which only the STDIO transport supports: over the stateless HTTP transport they throw `UnsupportedOperationException`.
