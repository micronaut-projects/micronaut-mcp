In a method annotated with `@ResourceTemplate` you can bind parameters with types:

- api:mcp.server.context.MicronautMcpTransportContext[]
- `io.modelcontextprotocol.spec.McpSchema.ReadResourceRequest`

Additionally, you can add method parameter matching the uri template variable as show in the previous example.

Variable values are percent-decoded as UTF-8 before they are bound, so `book://book/A%20Tale` binds `A Tale`. This is URI decoding, not form decoding: `%2B` binds `{plus}`, and a space must be sent as `%20`, not as `{plus}`. A simple variable such as `{title}` does not match a literal `{plus}`, so clients must encode it as `%2B`; in reserved variables such as `{+path}` a literal `{plus}` stays a `{plus}`. A malformed escape, such as `%zz`, or escaped bytes that are not valid UTF-8, such as `%FF`, are answered with an invalid params error.

The URI is matched before it is decoded, so a simple variable such as `{title}` matches a single segment, and a value that contains an encoded `/` (`%2F`) is rejected with an invalid params error. A value that may contain `/`, such as `AC/DC`, needs a reserved variable: `{+title}`. The single-segment rule assumes the default pattern of a variable: a variable with a regular expression, such as `{path:.*}`, can match a literal `/`, while an encoded `/` is still rejected.

WARNING: Rejecting an encoded `/` does not make a value safe to use as a path. Decoded values may still be `..`, contain `\` (`%5C`) and control characters such as `%00`, and the values of reserved variables may also contain `/`. Validate every value before you use it, for example to resolve a file or to build a query.
