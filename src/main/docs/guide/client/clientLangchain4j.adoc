To use an https://docs.langchain4j.dev/tutorials/mcp#mcp-client[MCP Client powered by LangChain4j], use the following dependency:

dependency:micronaut-mcp-client-langchain4j[groupId=io.micronaut.mcp]

Declare a named connection for each MCP server, over Streamable HTTP or STDIO. Connections of both transports can be used together:

[configuration]
----
micronaut:
  mcp:
    client:
      http:
        weather:
          url: https://weather.example.com/mcp
          headers:
            Authorization: Bearer ${WEATHER_TOKEN}
          request-timeout: 30s
      stdio:
        files:
          command:
            - npx
            - -y
            - "@modelcontextprotocol/server-filesystem"
            - /tmp
          environment:
            DEBUG: "false"
          auto-health-check: false
----

For each connection there is a `dev.langchain4j.mcp.client.McpClient` bean, qualified by the name of the connection, which is also the key of the client. A `dev.langchain4j.mcp.McpToolProvider` bean provides the tools of every client to LangChain4j AI services, and a `McpToolProvider` bean qualified by the name of a connection provides only the tools of that client.

Declare beans of these types to customize the clients and the tool providers:

- `io.micronaut.mcp.client.langchain4j.McpToolFilter` selects the tools that the tool providers provide.
- `io.micronaut.mcp.client.langchain4j.McpToolNameMapper` names them, for example to prefix them with the client key so that the tools of different servers cannot clash.
- `dev.langchain4j.mcp.client.McpClientListener` and `dev.langchain4j.mcp.client.logging.McpLogMessageHandler` are registered with every client.

With Micronaut Management, the `mcp` health indicator pings every server concurrently, and reports each connection whose server cannot be reached, or whose client cannot be created, as down. The servers that do not answer within `endpoints.health.mcp.timeout` (default `10s`) are reported down. Disable the indicator with `endpoints.health.mcp.enabled=false`.

A client is created when it is first used, which initializes the connection to its server. The `McpToolProvider` bean of every client skips the servers that cannot be reached, and creating their client is attempted again the next time the tools are provided. The `request-timeout` of a connection also applies to the pings of its client.

By default, each client checks periodically that its server is reachable, and reconnects when it is not. Disable it for a connection with `auto-health-check: false`. For STDIO connections, a reconnection starts a new server process, so consider disabling it for servers that are slow to start, such as those started with `npx`, or that cannot run twice.

The `langchain4j.mcp.client.transport.stdio.commands` property is deprecated: it declares a STDIO connection named `stdio`.

If you are building an MCP Server, you can test it by injecting a bean of type `dev.langchain4j.mcp.client.McpClient` in your tests.
The MCP Client pointing to your MCP Server has a name qualifier with value `embeddedServer`.

To customize client creation further, define a
https://docs.micronaut.io/latest/api/io/micronaut/context/event/BeanCreatedEventListener.html[BeanCreatedEventListener]
for `DefaultMcpClient.Builder`, `StreamableHttpMcpTransport.Builder` or `StdioMcpTransport.Builder`.

== Authorization

To call MCP servers on behalf of the user, set `propagate-authorization` on an HTTP connection: the `Authorization` header of the HTTP request the application is handling, such as the user's bearer token, is sent to the MCP server.

[configuration]
----
micronaut:
  mcp:
    client:
      http:
        weather:
          url: https://weather.example.com/mcp
          propagate-authorization: true
----

To compute headers for each request otherwise, for example to send an OAuth access token that is refreshed, declare a bean of type `io.micronaut.mcp.conf.client.McpClientHeadersProvider`. Both apply to the LangChain4j and the Java SDK clients, and are evaluated on the thread that calls the client: call it from the thread handling the request for the `Authorization` header to be propagated.
